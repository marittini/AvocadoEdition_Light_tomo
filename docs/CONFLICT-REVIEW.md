# 기능 연결부 충돌 점검

대상: 기능 PR #3 및 기존 아보카도 개선판. 운영 데이터가 아닌 격리된 PHP 8.4.27 + MariaDB + Chromium 환경에서 확인했다.

## 재현하여 수정한 문제

| 영향 | 재현 조건과 이전 결과 | 수정 |
|---|---|---|
| 새 폰트 연속 저장 실패 | 새 등록 폰트를 적용하고 저장한 뒤 새로고침 없이 다시 저장하면, 화면의 빈 ID가 다시 생성되어 사용 중 폰트 삭제로 판단하고422 반환 | 저장 응답에 확정 ID를 포함하고 요청 이후 변경되지 않은 폼 필드에 반영 |
| 미저장 내용의 상태 표시 오류 | 저장 요청을 지연시킨 동안 제목 등을 추가 수정하면 첫 요청 응답이 나머지 변경까지 저장 완료로 표시하고 이탈 경고도 해제 | 폼별 수정 버전을 비교해 요청 이후 수정은 미저장 상태로 유지 |
| 업로드 이미지 설정 유실 | 이미지 업로드 저장 후 화면의 경로 입력은 이전 값으로 남음. 파일 없이 다시 저장하면 빈/이전 경로가 저장됨 | 서버 확정 경로를 폼에 반영하고 성공한 파일 입력만 정리. 요청 중 새로 선택한 파일/새 입력은 유지 |
| 파비콘·커서 상호 덮어쓰기 | 같은 확장자의 두 이미지를 등록하면 모두 `site_favicon.*`에 저장되어 마지막 파일로 덮어씀 | 커서는 별도 `site_cursor.*` 파일명 사용 |
| 썸네일과 업로드의 자원 설정 충돌 | 썸네일 라이브러리를 include하면 `memory_limit=-1`이 전체 요청에 적용되어 이후 업로드의 메모리 상한 검사도 무력화 | 전역 제한 해제 제거. 새 썸네일 생성 전에 소스/대상 메모리를 추정해 부족하면 반환. 기존 캐시 재사용은 제한 없이 허용 |

파비콘/커서를 이전 버전에서 같은 경로로 저장했다면 이미 덮어쓴 파일은 복원할 수 없다. 업데이트 후 각각 원본 이미지를 다시 등록해야 한다.

## 검증

- `tests/settings_interaction_smoke.cjs`: 수정 전 연속 저장422·미저장 상태 오류·파일명 충돌·업로드 경로 유실을 재현했고, 수정 후 통과했다. 새 폰트와 디자인 이미지 연속 저장, 설정 저장 중 추가 입력, 서로 다른 PNG 파비콘/커서의 URL·해시 분리도 확인했다.
- `tests/tomo_settings_test.php`: 썸네일 포함 전후 메모리 제한 보존, 낮은 메모리에서 새 생성 거부·기존 캐시 사용을 추가 검증했다.
- 공유 관리자 저장 스크립트 변경에 대해 기존 관리자·편집기·게시판 및 새 기능의 통합 테스트를 재실행하여 통과했다.

## 점검 범위 밖과 남은 구조적 제약

개인 스킨과 외부 SNS/메일 등 모든 플러그인의 조합을 완전 검증한 것은 아니다. 실제 호스팅의 GD/메모리/Apache 정책은 별도 확인이 필요하다.

기존 디자인 저장은 DB 변경과 CSS 파일 교체를 하나의 원자적 작업으로 처리하지 않는다. 파일 생성/교체가 실패하면 UI에는 실패가 표시되지만 DB 일부 값이 이미 바뀔 수 있다. 이번 수정은 이를 트랜잭션으로 바꾸지 않는다. 파일·DB를 함께 다루는 저장 모듈과 실패 복구는 별도 리팩토링 대상이다. 이 항목은 코드 흐름으로 확인했으며, 이번 정상 저장 조합 테스트와 구분한다.
