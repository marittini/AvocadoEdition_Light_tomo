# 닷홈 PHP 8.4 설치·업데이트·복구

현재 코드는 검증 브랜치입니다. 닷홈 실배포는 수행하지 않았습니다.

## 새 설치

1. PHP 8.4 계정에서 mysqli, GD의 WebP 지원, mbstring, iconv, EXIF, 업로드 크기/메모리, UTF-8 DB, HTTPS와 Apache mod_rewrite를 확인합니다. 실제 로그인·비공개 자료는 HTTPS 확인 후 사용합니다.
2. 저장소 안쪽 `AvocadoEdition_Light/`의 **내용물**을 호스팅 웹 루트에 전송합니다. `.git`, 테스트 코드, 문서, 검증용 DB/비밀키는 전송하지 않습니다.
3. `data` 폴더를 만들고 서버 PHP가 쓸 수 있게 합니다. 과도한 전체 쓰기 권한 대신 호스팅 안내에 맞는 소유권/권한을 사용합니다.
4. `/install/`에서 DB와 관리자 정보를 설정합니다. 설치 후 `install` 웹 접근은 호스팅에서 차단하거나 폴더를 따로 보관합니다.
5. 데이터 폴더에 생성된 `.htaccess`를 확인합니다. 새 파일/편집기 직접 URL이 `bbs/archive_file.php` 권한 검사를 거치는지 비로그인 브라우저로 시험합니다. PHP 개발 서버로는 이 동작을 검증할 수 없습니다. rewrite가 없으면 데이터 폴더는 차단되도록 설계했습니다. 호스팅에서 Options/Require/RewriteRule을 제한한다면 그대로 공개하지 말고 설정을 조정해야 합니다.
6. 환경설정, 디자인 저장, 메뉴, 글/파일 업로드·조회·삭제를 확인합니다. 캐릭터/mmb/기존 세부 기능은 실제 사용할 스킨으로 검증합니다.
7. 디스크 측정은 앱이 읽는 파일의 합계입니다. DB·계정 밖 파일·호스팅의 실제 한도와 별도 대조하세요.

## 기존 설치 업데이트

1. 파일과 DB 전체를 **서버 밖으로** 백업합니다. 잠시 쓰기 작업을 중지하고 복원 가능성을 확인합니다.
2. 기존 `data/`, DB 설정과 개인 스킨/수정 파일을 덮어쓰거나 삭제하지 않습니다. 변경 파일 차이를 비교해 프로그램을 갱신합니다.
3. 새 권한 게이트를 사용하려면 `install/data-protection.htaccess`와 기존 `data/.htaccess`를 비교·병합합니다. 기존 호스팅별 설정을 무조건 덮어쓰지 않습니다. 규칙 적용 전에는 직접 URL 보호가 완료된 것이 아닙니다.
4. 테스트 사이트에서 먼저 검증합니다. 새 업로드는 WebP 변환·검증 후 원본을 삭제합니다. 변환 실패 시 원본을 유지합니다. 변경하지 않은 기존 이미지의 일괄 변환/삭제는 수행하지 않습니다.

## 수동 백업·다른 호스팅으로 복구

- 백업 시 파일+DB가 일치하도록 쓰기를 중지합니다. 전체 프로그램/개인 스킨/`data`와 DB SQL을 함께 보관합니다. 백업에는 DB 비밀번호·비공개 기록이 있으므로 공개 Git이나 웹 폴더에 넣지 않습니다.
- DB는 phpMyAdmin의 구조+데이터 내보내기(SQL)로 보관합니다. 파일은 SFTP/호스팅 백업 기능 등으로 내려받고 파일 수/크기/해시를 확인합니다.
- 다른 호스팅에 동일 프로그램·파일을 복원하고 DB를 가져옵니다. `data/dbconfig.php`의 연결 정보를 새 계정에 맞게 수정합니다. 고정 도메인·개인 코드의 주소도 확인합니다.
- 새 환경에서 로그인, 글/댓글·그림·자료, 원본/WebP 연결, 메뉴·디자인, 비공개 직접 접근, 파일 삭제를 시험합니다. 성공한 뒤에 공개 주소를 전환합니다.
- 장애 시 프로그램과 파일만 되돌리거나 DB만 되돌리는 혼합 복구는 피합니다. 같은 시점의 사본으로 함께 복원합니다.

## 웹폰트·품질·보호 설정 업데이트

새 기능 배포 후 최고관리자로 디자인 설정 또는 환경설정을 열면 전용 설정 필드를 누락분만 추가합니다. DB 계정의 ALTER 권한을 확인하세요. 새 WebP 변환의 기본값은 95이며 관리자에서 0~100으로 변경할 수 있습니다. 기존 파일 일괄 재변환은 하지 않습니다. 사용법과 되돌리기는 [FONTS-MEDIA-PROTECTION.md](FONTS-MEDIA-PROTECTION.md)를 참고하세요.

## 디자인 저장 복구 모듈 업데이트

DB의 LOCK TABLES 권한, CSS/이미지/복구 폴더 쓰기와 flock·rename 지원을 확인하세요. 배포 전에 열린 디자인 폼은 새로고침합니다. 미완료 복구 기록을 삭제하거나 복구 전에 구버전으로 되돌리지 마세요. 상세 배포·장애 대응은 [DESIGN-SAVE-RECOVERY.md](DESIGN-SAVE-RECOVERY.md)를 참고하세요.
