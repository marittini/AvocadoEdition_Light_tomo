# 설정·편집기 보완 및 업데이트 전용 묶음

빈 편집기가 `<p></p>`를 저장해 공지 박스를 표시하던 문제를 수정합니다. 실제 글자가 없는 문단·줄바꿈·보이지 않는 공백은 빈 문자열로 보냅니다. 이미지·표·영상·구분선은 보존합니다. 게시판 공지 저장에도 같은 처리를 적용하며, 이미 저장된 빈 문단은 공지 출력 시 무시합니다. DB 내용을 일괄 삭제하지 않습니다.

홈페이지 상세관리는 구역마다 반복되던 저장 버튼을 하나로 모았습니다. 탭 패널의 불필요한 포커스 테두리도 제거했습니다. 원본의 연분홍·회색과 사각 컨트롤을 유지합니다.

편집기는 관리자 화면에서도 실제 등록된 글꼴을 로드합니다. 사이트 테마의 일반 선택자는 관리자에 적용하지 않고 글꼴 선언만 가져옵니다. 도구를 선택할 때 텍스트 범위를 보존하며, 지연된 포커스가 이전 선택 영역으로 돌아가는 경로를 제거했습니다. 커서를 다른 문단으로 옮기면 글꼴·크기·정렬 표시도 해당 위치에 맞춥니다.

## 색상 일괄설정

**디자인 설정 → 색상 일괄설정**에서 사용합니다.

- 로즈·세이지·라벤더·모노 팔레트 또는 강조색 기반 추천을 선택합니다.
- 페이지 배경·상자 배경·본문·강조색·구분선·보조 글자를 한곳에서 조정합니다.
- ‘디자인에 일괄 적용’으로 관련 기본색·입력창·버튼·메뉴·게시판·로드비 항목을 변경합니다.
- 상단 저장을 누르면 기존 디자인 저장 경로를 통해 반영됩니다. 자동 적용하지 않습니다.
- 배경 이미지, 글꼴, 크기, 투명도는 유지합니다. 개별 수정도 계속 가능합니다.
- 되돌리기는 이번 일괄 적용으로 변경한 값을 복원합니다. 그 이후 별도로 수정한 값은 유지합니다.

색상 대비 수치는 불투명 색상끼리 계산한 참고값입니다. 배경 이미지와 투명도를 사용하면 실제 대비는 달라질 수 있습니다.

## 회원가입 승인

**환경설정 → 회원가입 승인 → 새 가입자는 관리자 승인 후 이용**을 켭니다. 기본환경의 ‘계정생성 가능’도 켜져 있어야 합니다.

- 기존 회원은 승인 상태를 기본값으로 추가하여 그대로 이용할 수 있습니다.
- 켠 뒤 가입한 계정은 승인 대기로 저장되며 자동 로그인되지 않습니다.
- **회원관리 → 가입 승인**에서 대기·승인·거절 목록을 보고 선택 처리합니다.
- 최고관리자 계정은 승인 상태로 잠기지 않으며, 승인 관리에서 상태 변경도 차단합니다.
- 일반회원은 승인 관리에 접근할 수 없습니다. 변경 요청은 관리자 토큰을 확인합니다.
- 대기·거절 계정은 비밀번호를 맞게 입력해도 로그인되지 않으며, 이미 열려 있던 로그인도 다음 요청에서 해제합니다. 자동 로그인에도 같은 조건을 적용합니다.
- 이메일 인증과 회원 등급·게시판 권한은 별도로 유지합니다.
- 가입 승인을 끄면 이후 새 가입은 기존 방식대로 처리합니다. 기존 대기·거절 계정은 자동 승인하지 않습니다.

설정과 회원 테이블에 필드를 추가하는 방식이며 기존 회원 행을 초기화하지 않습니다. 추가 마이그레이션에는 설치 시와 같은 테이블 변경 권한이 필요합니다. `LOCK TABLES`나 서버 root 권한은 사용하지 않습니다.

## 홈페이지 가입 화면과 트위터 아이디

가입 승인 대기와 일반 가입 완료 화면은 기존 회원 스킨의 제목·안내 상자·버튼을 사용합니다. 홈페이지 가입 안내이며 캐릭터 생성·합격 안내는 표시하지 않습니다.

신규 가입에는 트위터 아이디가 필수입니다. 영문·숫자·밑줄 1~15자를 `@`를 붙이거나 빼고 입력하면 `@` 없이 저장합니다. 기존 회원의 정보 수정은 선택 입력이며, 관리자 회원 상세에서도 확인하고 수정합니다. 기존 생년은 별도 필드에 보존합니다. 계정 생성 기간이 종료된 뒤에도 회원정보를 수정할 수 있습니다.

업데이트 후 최고관리자로 관리자 페이지에 접속하면 별도의 회원 필드가 추가됩니다. 기존 데이터를 초기화하지 않지만 DB의 테이블 변경(ALTER) 권한이 필요합니다. 권한이 없다면 관리자 화면에 안내가 표시되고 가입을 진행할 수 없으므로 호스팅 업체에 확인해야 합니다. 기존 회원과 관리자 로그인을 차단하지 않습니다. 새 설치에는 필드가 포함됩니다.

## 세션·캐시 정리

일상 운영의 필수 메뉴가 아니므로 **디스크 사용량 → 고급 정리 도구**로 옮겼습니다. PHP에는 기존 자동 세션 정리가 설정되어 있으며, 최신글 캐시는 조회 시 다시 생성됩니다.

정리 화면은 GET으로 열기만 하면 파일을 삭제하지 않습니다. 최고관리자의 POST와 토큰이 있어야 실행합니다. 세션은 마지막 수정 후 6시간이 지난 파일만 대상으로 하며 현재 세션은 유지합니다. 캐시는 `latest-*.php`만 대상으로 합니다. 심볼릭 링크·디렉터리·다른 파일은 건너뛰고 실제 삭제 성공 수와 실패 수를 따로 표시합니다.

## 업데이트 적용

전체 설치 ZIP 대신 `updates/avocado-tomo-update.zip`을 사용합니다.

1. 복구해 놓은 현재 서버 파일과 DB를 백업합니다.
2. ZIP을 풀고 **UPLOAD 폴더 안의 내용만** 기존 `common.php`가 있는 위치에 업로드합니다.
3. 같은 경로의 변경 파일만 덮어씁니다. 서버 디렉터리 삭제나 동기화 삭제는 사용하지 않습니다.
4. 설치 화면은 다시 실행하지 않습니다. 최고관리자로 관리자 페이지에 접속해 회원 필드를 준비하고 설정과 첨부 기능을 확인합니다.

이 묶음에는 `data/`, `install/`, 프로그램 최상위 `config.php`가 없습니다. DB 연결 설정·첨부파일을 포함하지 않으며, 추가 설치한 사용자 스킨/플러그인을 지우는 동작도 없습니다. 단, **목록에 있는 프로그램 파일 자체를 직접 수정했다면 그 수정은 덮어써질 수 있으므로** `PATCH_FILES.txt`와 대조해 백업해야 합니다.

기준은 기존 PHP 8.4 TOMO 버전(PR #3 이후)입니다. PR #5의 신규 편집기 파일도 포함하여 업데이트 구성의 누락을 방지합니다. 사용자가 임의로 바꾼 모든 서버 파일과의 호환성을 보장하는 자동 설치기는 아닙니다.

개발 환경에서 재생성:

```sh
python3 tools/build_update.py --base c3c1f3ee0eb56c73c1f5be9e47fd0edb8f5d305c --revision HEAD --output updates/avocado-tomo-update.zip
python3 tests/update_archive_test.py updates/avocado-tomo-update.zip
```

Git에 커밋한 프로그램 파일만 패키징하고 파일별 해시를 기록합니다. 검증에서는 임시 설치에 ZIP을 덮어써 DB 설정·기존 첨부·사용자 스킨·플러그인 보존을 확인합니다. 실제 닷홈 서버에서 복구나 덮어쓰기를 실행한 것은 아닙니다.
